# CityMETER Fitness — owner preferences

Set 2026-10-29 (release 0.1.0) on the owner request “ทำแบบเดียวกัน [กับ CityMETER: Luxury Brands] ให้กับ CityMETER: Fitness แล้ว publish ที่ github.com/montri-th/fitness”, carried over from CityMETER · Luxury Brands 0.5, Restaurants 0.5 and Pharmacy 0.1.1 where the same contract applies. Release 0.2.0 (same day, owner 19:47) adds the building view of CityMETER · Shopping centers and Luxury Brands — “เช็คอย่าให้ 3d building mass ตึกอื่นบังอาคารที่กำลังดูอยู่ … อาคารที่เลือก หรือ on focus ให้แสดงด้วยมุมมอง 2-point perspective เสมอ zoom to fit viewport เสมอด้วย · ร้านเครือ กับ ร้านในอาคาร (sheet 1+sheet2) ให้แสดงรวมกันไม่ต้องแยก” — and the owner's standing rule for colour scales (“Color scale ขอให้ใช้ 41 scales ตาม LDS เสมอ”). Release 0.3.0 (owner 2026-10-29 23:32) puts the brand before the branch — “มันควรต้องเอา logo + brand ขึ้นก่อน ชื่อสาขามั้ย ทั้ง map ป้าย และ side bar และที่อื่นๆ” — shortens the panels (“กระชับ เน้นภาพ logo icon charts symbol … เห็น Aha เร็ว”) and adds the next question of each view in Google (“google search AI mode, streetview, search ด้วย context ที่ relevant กับ เสียงในหัวของ user ในขณะนั้น”).

- Apply current LDS 0.9.7 (v0.9.7-owner.1, standalone-0.9.7-r1, color-srgb-10) and preserve the map-first CityMETER layout. Colours come only from `assets/theme.css`, `js/scales.js` and `js/cues.js`; never approximate a value by eye. Analytical colours are the same HEX on both themes; EVID-05 map treatments use the `dataState` tokens (`--data-no-data`, `--data-zero-outline`). `npm run check:lds -- --lds <file>` compares every shipped LDS value with the source file.
- Read `PRODUCT_STATEMENT.md` before changing what the first screen argues. The question is “สาขาฟิตเนสกระจุกอยู่ตรงไหน และเป็นฟิตเนสแบบไหน”.
- Counting unit is a contract (`js/model.js#unitWords`, `filterRows`): the default counts rows whose official source still lists the branch on the check date (status `listed`, “สาขา”). Announced, closed and review rows are counted apart as “รายการ” and never added to the listed figure; the overview names them in one line. The research covers a declared set of brands: never call a figure a market share, a market size, a density or a footfall.
- Aha first, in 3D: the first paint is the `city` preset framing up to three เขต/อำเภอ with the most listed branches in the province that holds the most branches placed at district level, focused automatically (`auto`, no `areas` param). Show the share (Σ focus ÷ the province's placed branches), numerator and denominator, the province's branches placed only at province level, the studio-share comparison (focus vs the rest of the province, both bases stated) and the district(s) with the most branches outside that province, then the actions (ดูทุกพื้นที่, เปรียบเทียบพื้นที่). Never cut through a tie (`js/area-insight.js`): only districts strictly above the next one are the focus; all equal → the “spread” Aha; an outside top of 1 is not shown. Snapshot numbers in the handoff JSON are fixtures, never UI constants.
- Metric choice is a contract: totals (`count`) for เขต/อำเภอ, province frames and matrix cells; no per-area or per-person ratio is drawn. Colours use all 41 samples of the LDS `count` LUT (owner standing rule): `buildRamp` gives each value the sample of its rank among the measured nonzero values being read (lowest 0, highest 40, ties share, nothing interpolated); the map, the legend (41 samples + value ticks, `rampLegendHTML`), the labels and the count chart read the same ramp; the matrix has its own ramp over its cells; numbers on samples 27–29 sit on a plate. Never go back to a 3/5-class pick.
- Membership is the district matched at build time from the row's own data (`row.admin`: point · host · address · province · conflict · none; `row.how` for addresses). Never re-assign by point-in-polygon on display coordinates or by a branch or brand name at runtime. A province disagreement is placed nowhere and reported (`meta.conflicts`). Rows without a district stay in every total and are named apart (“ระบุได้แค่จังหวัด”, “ไม่ระบุจังหวัด”, “ข้อมูลจังหวัดขัดกัน”).
- National scale: `data/area-index.json` has every district without geometry (ranks, panels, charts and camera fits work at once); outlines load per province (`js/frames.js`) for the selection and for the provinces under the map at district zoom (≤ 6 per move). Never load all 77 frame files up front.
- EVID-05: every district is in the research scope, so a district without a row is a measured zero of this dataset (“ไม่มีแบรนด์ใดในชุดข้อมูลที่หน้าทางการระบุสาขาในพื้นที่นี้”), never no_data; points are missing for most rows and are never invented.
- Focus + quiet context: detail (fills, coloured cue symbols, rounded focus massing) only for the focused part — the selected district, the venue, the automatic or explicit focus. Everything else stays visible but quiet. Below zoom 8 the province frames (count) carry the reading — except with a จังหวัด filter (province view): the province is fitted whole and its own เขต/อำเภอ are drawn from zoom 4.
- Formats bind by stable id to LDS series with the series shape cue (`js/cues.js#GROUP_SERIES`; DATAVIZ-05). Never colour a category by hue alone; keep the cue in legends, lists, matrix headers, charts and map symbols. No star cue (it would read as a rating). “สตูดิโอ” = training, Pilates, boutique, yoga, combat and climbing (`js/model.js#FAMILY`).
- Brands, companies and venues join by the sheet's ids only. Company names are as the sources state them — say “ยังไม่ได้ตรวจกับทะเบียนนิติบุคคล” and that a missing record does not mean independent. “บริษัทเดียวกัน” = brands recorded with the same company id. Venues are CityMETER Shopping Center records linked by venue id (`common_retail_venue_ids` / `citymeter_shopping_center_id` with status `accepted_identity_and_located_in`); never infer a venue from a name or a distance. A venue missing from `07_SHOPPING_CENTERS` comes from the pinned registry snapshot (`--registry`, every file hashed into `meta.registry`); held candidates are never drawn as links. Link changes are made in the research sheet itself (owner 2026-10-29 “ผูกแล้วเขียนกลับเข้าชีตวิจัย”), then re-exported and rebuilt — never patched in `data/`.
- Brand first (INV26): wherever a branch is named, the brand logo (when present) and the brand name come before the branch (`js/ask.js#branchLabel` strips a repeated brand) — pins, popup, aria-labels, every list, the brand card, the district/venue/building panels, the table (brand column first), the brand chart and the document title. A logo never replaces the name.
- Logos (INV27) come only from registries: `data/brand-logos.json` (`scripts/build-logos.py` from `16_BRAND_LOGOS` + the library, every file SHA-256 checked; original bytes when display-sized, else a recorded uniform downscale / transparent-margin trim / SVG namespace fix, both hashes kept; no recolouring, tracing or upscaling) and `data/venue-logos.json` (the registry's venue logos, bytes unchanged). Chips (`js/logos.js`) use the library's recommended surface, the same in both themes; a display-surface correction is recorded in `SURFACE_OVERRIDE` with a note and reported to research. A missing or invalid logo only means no logo. Pins carry logo chips only where they fit without overlap (`placeLogos`: selected/hovered first, then nearest the centre).
- Outbound actions (INV28, `js/ask.js`): ถาม Google AI (AI Mode, `udm=50`) with a question written for the view, Google Maps search, and Street View only where the view has a point (“ใกล้อาคาร” for a venue's registry point, which is not the entrance). Public names and published points only, https, new tab with `noopener`; one line says the answers are Google's, not CityMETER data.
- Spatial join is display-time only (`js/building-join.js#joinBuildings`): row points and the CityMETER venues' registry points × focus-tier OSM footprints. One building = the pieces of one outline cut by z14 tile edges (same OSM id + shared cut points, never the id alone), the building:parts inside a `hide_3d` outline, and every drawn part holding one point (podium + tower). Say “จุดตกในอาคาร”, never “ตั้งอยู่ใน”. It never changes a count.
- One list per building (owner 2026-10-29, `buildingRows`, `venueRows`): the rows the sheet links to a venue whose registry point falls in the building and the rows whose own points fall in it, each once, in one list — the venue panel, the building panel, the table and the pins show the same rows. A building that holds a venue's point opens that venue. The Fitness sheet has one branch population (`02_STORES`; 03/08/09 are views of it and are never added).
- Breadcrumb is ประเทศไทย › จังหวัด › เขต/อำเภอ (› ศูนย์การค้า) with production codes and deep links `/v3/citymeter/{code}/D/{district}` (production has no fitness dataset yet: no `?d=`). A branch is the panel heading, never a crumb. A selection in another province moves the จังหวัด filter with it.
- Every panel view ends with exactly one provenance line — dataset · source · date · boundary — and one clause on what the counted unit is (`provenance()` in `js/panel.js`). Keep other caveats out of popups, tooltips and lists (owner, Restaurants 0.4.0: “caveats … เอาให้เนียน นึกถึง user benefit เป็นหลัก”).
- Basemap, massing and camera follow the Luxury Brands contracts (`js/map-style.js`, `js/massing.js`, `js/camera.js`): basemap tokens only, OSM heights are context, presets never move data, keep every 3D preset at pitch ≤ 90° − fov/2 − 3°. The first Aha's three Bangkok districts need exactly 16 z14 tiles (`MAX_TILES`), so the focus tier draws from zoom 12.
- Building view (owner 2026-10-29 19:47; the Shopping centers venue camera): the building being looked at (`focusTarget`: the open venue's building, the open building, the open branch's building) is framed by `frameFocus` → `fitBuilding` — eye preset (pitch 75°, fov 24°), padding zero, bearing = dominant wall + 45° on the diagonal where the drawn focus buildings hide least (`twoPointBearing`), every footprint and roof vertex filling the free box (`visibleBox`: below the toolbar, above the tray, legend, table or open sheet, left of the zoom control), up to zoom 21 (`BUILDING_MAX_ZOOM`; Fitness branches stand in shophouses and small buildings, so the Shopping centers limit of 19.5 left them half-size). The fit uses the pieces as the focus tier draws them at building zoom (`massing.fitPointsOf` → `footprintFitPoints`, the offset and fillets of zoom 18), never the shape drawn at the zoom the camera starts from (up to 3.6 m wider on every side). Unknown building → a 90 m box round the point, then one turn to the building when it arrives (≤ 2 refits, never after a user camera move). Every way in frames again (pin, building, x-ray tap, list, table, search, URL, back, ดูทั้งหมด, sheet open/close, 3D toggle). The building is drawn over every other building and over road names by the x-ray (`js/venue-xray.js`, before `place-quarter`), the focus buildings in front of it turn see-through (`massing.setScene('eye')`), district labels never sit on it, and every GeoJSON source uses `maxzoom: 24` (`GEOJSON_MAXZOOM`, two levels above `BUILDING_MAX_ZOOM`). Do not reorder the massing, x-ray and pin layers casually.
- MapLibre stays pinned at 5.6.2 with `js/maplibre-guard.js` (0.2.1, found in the live walk): its tile cover throws “reading 'key'” when a pitched camera zooms out through 13–14 on the OpenFreeMap vector source (maxzoom 14) right after a building view; `guardRetainedTiles` (installed on every style load) pads the one overscaled child of those ideal tiles so MapLibre's own overzoom rule applies. Re-check the bug and the guard (`tests/maplibre-guard.test.js`) before upgrading MapLibre.
- One symbol always represents one row with a point; never cluster or aggregate. HTML pins from zoom 15.5 inside the focus only (≤ 320); quiet context dots are never focusable or clickable.
- Copy: short, natural Thai — สาขา / รายการ / แบรนด์ / รูปแบบ / สตูดิโอ / ยิม / เขต·อำเภอ / ศูนย์การค้า / บริษัท; lead with pictures (logo, pictogram, status pill, fact chips) and keep sources, methods and ids behind one “แหล่ง สถานะ และพิกัด” disclosure; units on every number; a number and its unit never split across lines (`nw` in `js/panel.js`). No static counts in page copy (help, meta): numbers come from the data.
- Charts: matrix cells are equal in size; bars carry the map's ramp colour (districts) or the format series with its cue (brands, labelled logo + name). No CSV download. No decorative brackets or coloured left rails. Visible focus everywhere.
- Privacy and publication: never copy addresses, floors, phone numbers, map links, researcher notes, README text or raw source records; source links are public https pages only. Never commit the internal research sheet or its export, private Drive/Sheet URLs, credentials or the full LDS library. Review Thai at desktop and 390 px in light and dark before claiming done; local renders are not proof of a live release — run `npm run verify:live` and walk the live site.
- Releases bump one cache tag `?v=YYYYMMDD-rN` on every entry in `index.html` and, through the import map there, on every ES module (the frame files take the same tag from `import.meta.url`), together with `package.json` version, `design-intent.json` and the handoff JSON `productVersion` (`tests/release.test.js`). A new module must be added to the import map. Icon fonts inside the stylesheets carry `?v=<first 8 hex of their SHA-256>` (INV29, `tests/icons.test.js`): the 0.3.0 live walk found Chrome keeping the 0.2.1 pictogram binary for the unversioned URL, so the new action icons drew as empty boxes.
- MapLibre's CSS loads after `styles.css`: control and attribution rules are scoped under `.map-panel`; the phone legend and Aha card sit above `--attrib-height` (`js/app.js#trackAttribution`). The phone-portrait toolbar holds five buttons in one row; วิธีใช้ and the product statement live at the top of the sheet. A camera fit jumps the map many times in one task: coalesce heavy work to after the last move (`scheduleLabelView`).
